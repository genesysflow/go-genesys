What each part is here to show

Routing & policies

Every writing route carries the policy that governs it, so a handler never runs for a caller who may not.routes/blog.go

Form requests

Prepare, authorize, rules, messages, after — a browser gets its input back, a JSON client gets a 422.app/http/blog/requests.go

ORM & relations

A post belongs to an author, has comments, carries tags polymorphically and can have files attached.app/models/blog.go

Queues & mail

Publishing dispatches an event; the listener queues the job that notifies the author.app/jobs/publish_post.go

Token API

The same posts served as JSON, authenticated with personal access tokens and their abilities.app/http/blog/api.go

Console & schedule

blog:stats for the numbers, a nightly prune and a queued weekly digest.app/console/blog_stats.go

GET / home

Handler
A closure rather than a controller, because one page with three counts does not need one.routes/web.go
Layout
layouts.blog, set once as the default in config rather than named by every page.config/view.yaml
Helpers
route, asset, config and csrf_field come from the view manager; errors, old and user are shared with every template per request.http/view_data.go
Assets
One stylesheet, served from public/ at /assets. No build step.routes/routes.go
This rail
Plain markup in each template. Nothing generates it, which is why it cannot drift silently — if it is wrong, the page is wrong.
